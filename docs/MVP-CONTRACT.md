# MVP implementation contract

This is the original v0.1 contract. Later additions are specified in [Connected Review](CONNECTED-REVIEW-CONTRACT.md) and [v0.3 process maps and source revisions](V03-IMPLEMENTATION-CONTRACT.md). The latter adds authorized source corrections with preserved history to the original immutable-source model.

Independent Workwork Cloud, Node 22.14+ ESM, built-in HTTP and `node:sqlite`, vanilla browser JS/CSS. No production data or old service integrations. Multiple companies self-register; server-derived workspace and role scope every query. Local synthetic demo is optional; normal registration starts empty. Railway deployment uses one service replica with a persistent volume mounted at `/data`, `DATABASE_PATH=/data/workwork.sqlite`, `NODE_ENV=production`, `HOST=0.0.0.0`, platform PORT. No automatic public demo credentials. Subscription payments are outside this pilot.

## Shared module boundaries

- `server/store.mjs`, `server/app.mjs`, `server/auth.mjs`, `tests/api.test.mjs`: backend owner.
- `server/analysis.mjs`, `tests/analysis.test.mjs`: extraction/review owner. Pure functions only, no filesystem/network.
- `public/index.html`, `public/app.js`, `public/styles.css`: frontend owner.
- Root owns package.json, Dockerfile, railway.json, deployment docs, integration, additional checks, seed fixtures, optional AI adapter.

## API

JSON responses, errors `{error: string}`. Session cookie HttpOnly, SameSite=Lax; Secure in production. Same-origin mutation checks. All data APIs authenticated. Goals/tasks/requirements/invites manager-only. Work and own evidence allowed to members. Metric measurements manager-only in this MVP. Limit JSON body and validate field types/length/ranges. Server assigns author/workspace/time/IDs. No password/session tokens in responses or logs. Sign-up creates a company + its manager atomically. Email login is globally unique for this first MVP; a user belongs to one company. Password minimum 12 chars. Case IDs generated by server for newly created cases; client may supply an existing caseId from its company for continuation.

- `GET /api/health` -> `{status:'ok'}`.
- `GET /api/session` -> `{user:null}` or `{user:{id,name,email,role},company:{id,name},csrfToken?}`.
- `POST /api/signup` body `{companyName,name,email,password}` -> session + `{user,company}` (201).
- `POST /api/login` `{email,password}` -> `{user,company}`.
- `POST /api/logout` -> `{ok:true}`.
- `POST /api/invites` manager `{email}` -> `{invite:{email,token,expiresAt}}`; token returned once, manager shares join link themselves; no email delivery. `POST /api/join` `{token,name,password}` -> new member session `{user,company}`. Root test URL UI `/?invite=...`.
- `GET /api/state` -> `{user,company,goals,requirements,tasks,logs,cases,measurements,review,extraction:{mode:'rules',label:'Automatic text extraction · baseline'}}`.
- `POST /api/goals` `{title,description?,metricName,unit,target,baseline?,direction:'at_least'|'at_most',periodStart,periodEnd}` -> `{goal}` 201. Values must be finite; period ISO dates; latest comparable measurement for goal uses date in period, matching unit AND scope. `scope` optional at create defaults company scope but stored explicitly; return it.
- `POST /api/requirements` `{title,scope,trigger,steps:[string,...],effectiveFrom}` -> `{requirement}` 201. Manager created rule version 1, fixed steps immutable in initial MVP. Scope and trigger are human text; matching is provisional unless explicit case/requirement link. Return `id,title,scope,trigger,steps,effectiveFrom,version,createdAt`.
- `POST /api/tasks` `{title,description?,goalId?,caseId?,dueDate?}` -> `{task}` 201. Manager-authorized team task; no individual assignment needed in initial pilot. Return status `open`, ID, createdAt, etc. `PATCH /api/tasks/:id` `{status:'open'|'done'}` -> `{task}`; manager or workspace member may mark team task completed. Recorded completion is not KPI success.
- `POST /api/logs` `{text,result?,nextDependency?,caseId?,occurredAt?}` -> `{log,cases,analysis}` 201. Narrative required. Occurrence is optional: missing timestamp remains null (createdAt is only record time). `caseId` optional; continuation reuses existing company case. Source text stays immutable. Logs include analysis as below. Persist entire analysis JSON. Add new/reuse cases according to server strategy; no auto semantic merges without explicit stable identifier/continuation. See extraction contract.
- `POST /api/measurements` manager `{goalId,value,unit,scope,observedAt,source}` -> `{measurement}` 201. All required; source nonempty self-reported evidence reference, not verified integration. Record author and createdAt. Data entry source marked `manual`.

## Data records / extraction contract

Each record has `id` string and `createdAt` ISO, optionally `companyId` internal; frontend never supplies companyId.
Case `{id,title,reference?,createdAt}`.
Log `{id,text,result,nextDependency,caseId:null|string,occurredAt:null|string,createdAt,authorName,authorId,analysis}`.
Analysis function export `analyzeLog(log,{goals=[],cases=[],requirements=[]}={})` -> `{events:[{id,text,action,status:'completed'|'in_progress'|'planned'|'blocked'|'recorded',caseId:null|string,caseReference:null|string,sourceQuote}],associations:[{goalId,eventId,reason,confidence:'suggested',sourceQuote}],dependencies:[{fromEventId,toEventId,reason,confidence:'explicit'}],warnings:[string]}`. Caller supplies server log ID. Event IDs `${log.id}:1`, etc. Split multiple activities conservatively, no invented facts; Korean and English signals useful. Goal links labelled suggested association, never causal proof. Do not infer numerical actuals. Log result/nextDependency retained separately; do not manufacture event sequence from record order. Explicit reference means narrative identifiable order/lot etc, not generic goal keyword. New case for an unreferenced independent log; continuation keeps provided caseId unless event explicit reference contradicts it. Backend creates/reuses cases from `caseReference` within company, patches event caseIds; never trust client arbitrary IDs. Log may have many cases; log.caseId only for explicit continuation; backend can set single inferred case if only one unique event case.

Export `buildReview({goals=[],requirements=[],tasks=[],logs=[],cases=[],measurements=[]})` -> `{metrics:[{goalId,title,metricName,unit,scope,target,actual:null|number,gap:null|number,status:'no_data'|'met'|'gap',measurementId:null|string,source:null|string}],cases:[{id,title,events:[{...event,logId,occurredAt,recordedAt,authorName}],goalLinks:[{goalId,reason,confidence}],dependencies:[],requirements:[{requirementId,title,version,applicability:'suggested',steps:[{title,status:'evidence_found'|'not_evidenced',evidence:[{logId,eventId,quote}]}]}],tasks:{open:number,done:number},summary:{logCount,eventCount,caseCount,unlinkedEventCount},warnings:[string]}`. Metric gap signed as actual-target, UI labels delta; status uses direction. Measurements must match unit/scope/period; latest by observedAt. Steps use provisional evidence match only; never definitive compliance/violation. Chronology labelled evidence timeline, dependencies separate. Source links open log. Frontend tolerate missing arrays; empty states useful.

## Interface

Integration refinements: authenticated mutations require `X-CSRF-Token` returned by session/state. Analysis events also preserve `sourceField` (`text`, `result`, `nextDependency`), `caseBasis` and `caseAmbiguous` where applicable. Optional output and dependency evidence keeps its source field; dependency context is not proof of completed work. A leading explicit case heading scopes its own paragraph. Ambiguous multi-reference events remain without a case. Log submission may run optional validated AI extraction asynchronously within the request; failure falls back to baseline with a saved warning. Production requires an explicit HTTPS `APP_ORIGIN`. Actual observation/occurrence times more than one minute in the future are rejected.

Three views: Work / Goals / Review. Signed-out login, signup, invite join with real form validation. Work narrative with optional result, dependency, occurrence; case input via Continue this work, no forced mappings. Company name, account role, logout. Managers can create goals, process requirements, team tasks, measurements and invite members. Members see permitted records, create logs, complete team tasks. Review exposes source evidence, proposed links, case timelines, provisional required-vs-recorded steps, three kinds of gaps. No fake execution states, billing or connected AI claims.

Frontend fetch uses credentials same-origin; use plain strings/textContent for user input, no HTML injection. Refresh state after every successful mutation and preserve unsaved form on errors. Responsive, keyboard accessible, compact, polished desktop-first manufacturing workspace. Root will run API, isolation, algorithm, browser verification and fix integration.
